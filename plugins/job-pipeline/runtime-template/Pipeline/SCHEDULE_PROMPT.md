# One bounded local pipeline run

This prompt performs one requested run. It creates no recurring task. Use the exact private workspace and its virtual-environment interpreter in a host with local file/process capabilities; v0.1 full locking requires Windows.

1. Read `AGENTS.md`, `Pipeline/PIPELINE.md` and `WORKFLOWS.md`. Run onboarding status. If not ready, report missing categories and stop job work.
2. Start the explicitly bounded run holder with owner `scheduled-run`, retain its token and verify ownership throughout work. Contention/stale lock stops cleanly; never auto-clear it. Stop external actions when its lease ends.
3. Read current SQLite settings, generated state, private facts/preferences, submission mode and account registry. Discover actual search, browser, email and document capabilities.
4. Search only configured/requested scope, prefer available job-search/details tools, then reliable pages. Obtain descriptions and actual source/requisition/location evidence. Check duplicates and normalize bounded imports through canonical APIs.
5. Reload settings and apply candidate/setting guards before selection. Retry prepared transient jobs before new document work. Do not invent candidate facts or override employer, authorization, salary, seniority or VIE controls.
6. Build with the approved private creator, inspect every page and record exact document review hashes before docs_ready. Failed checks publish nothing.
7. In review_only, stop prepared. In approved auto_apply, obey the smaller of current remaining cap, requested bound and platform limits. Review/read back live destination, fields, consent and files; run current preflight immediately before final action.
8. Stop affected jobs at exact unknown/security/account/portal blockers. Do not guess. Record transient errors once per run. Require observed post-action receipt/sent evidence before guarded applied recording.
9. Synchronize/export canonical state after durable changes. In cleanup, request lock release, verify holder exit and close only target tabs except one documented stateful handoff.
10. Report counts, deadlines and actionable blockers without private-value dumps. Stay quiet on unchanged/non-actionable monitor state unless the user asked for periodic reports.

Only one Claude/Codex/manual/scheduled run may own this workspace. Scheduling itself needs a separate user request and the host's current scheduling tool. A schedule cannot enable auto-apply or raise the cap.
