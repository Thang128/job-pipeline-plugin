# Owner review checklist

## Behavior

- [ ] Installation starts no searches, account creation, applications or recurring tasks.
- [ ] New workspace is empty of candidate/job/account history, `review_only`, cap 0 and VIE disabled.
- [ ] Setup uses each user's own facts and CV, and visibly approved current creator comparison.
- [ ] Unknown candidate authorization blocks; sponsorship silence is distinct from refusal.
- [ ] Country order precedes large-group preference; role priorities and inclusive seniority are deliberate.
- [ ] Current employer and configured aliases/end employers are excluded.
- [ ] VIE worldwide/Belgium/allowance exceptions match intended behavior.
- [ ] Fit scoring and keyword classification limits are clear.
- [ ] Document changes invalidate hash-bound review.
- [ ] Final action uses current settings, job, cap, documents and live payload readback.
- [ ] `applied` requires observed confirmation; evidence metadata is not falsely presented as independent proof.
- [ ] Three distinct portal-failure runs escalate; browser absence remains retryable.
- [ ] One host/run owns mutable workspace; bounded helper and stale recovery are understood.
- [ ] UTC daily cap and v0.1 outcome/history limitations are acceptable.

## Release

- [ ] Read the full [how-it-works guide](HOW_IT_WORKS.md) and [configuration reference](CONFIGURATION.md).
- [ ] Inspect exact release inventory, archive contents and checksums.
- [ ] No personal source data, private files, credentials, initialized database, generated CV or real receipts.
- [ ] Fresh artifact extraction/bootstrap and disabled-submission checks passed.
- [ ] Unit/CLI validation is distinguished from actual Claude/Codex/browser loading tests.
- [ ] Windows, dependency/Pango prerequisites and unverified surfaces are stated accurately.
- [ ] License, publisher, GitHub repository and visibility are reviewed before publication.
- [ ] GitHub distribution is distinguished from official vendor-directory review/acceptance.
